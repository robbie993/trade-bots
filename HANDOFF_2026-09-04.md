## 1. Goal

**Beat SPY.** Net of costs, on a comparison that cannot flatter itself.

The standing principle the whole system is built on:

> **The system may always stop the bleeding, and may never start it.**

Cutting an allocation, pausing a firm, halting everything: automatic. Raising
an allocation, killing a firm for good, touching real money: a human decides.

**The working principle these two days added:**

> **A config constant is a claim about the data. The data is right there — ask it.**

Four separate bugs came from code trusting a configured number over the thing
in front of it. Where a measurement is possible, measure.

## 5. Failed attempts and wrong calls

The most valuable section. Everything here I said with confidence and then
disproved by measuring.

### The recurring bug class, now at eleven instances

**Something that only knows how to count, acting on an entity whose story has
already ended — or on a unit it never checked.** Previous handoff lists six.
Five more:

7. **Borrow prorated by a config constant** that described the live loop while
   the data stepped daily. 1/96th of the real cost.
8. **The Sharpe gap check** licensing a 45-minute gap against 86,400-second
   steps, so every step read as a break and `sharpe` came back `None` for every
   firm — no number at all, and nothing said why.
9. **The gulag counting down on a bar that oscillates.** `market.as_of()` is
   `max(bar.as_of)` and is *not monotonic* — a partial bar appears in one fetch
   and is gone from the next. An 80-bar sentence drained in ~2 hours.
10. **`file_successor` promising a guard it did not implement** — it asked for
    a name and stopped when the *names* ran out, breeding heirs five deep.
11. **A gulag release resurrecting a wound-up firm**, because a countdown
    finishing was treated as a decision about a firm.

### Things I was confident about and wrong about

- **"Live Sharpe was 2× too large."** It was not. I measured the median bar
  spacing across *all* observations, including restart gaps, when the returns
  are computed only from the unbroken tail. Measured correctly: 900s, matching
  the config exactly. **Live was never affected** — the damage was confined to
  the backtest path. I committed the same units error inside the fix for it.
- **"The dashboard is slow because of a missing index."** I wrote a migration,
  applied it, and measured: **79.5s vs 81.4s — no improvement.** The real cause
  was a cold fetch of 36 symbols (81s cold, 0.03s warm). Migration removed
  rather than left in with a comment claiming a fix it did not deliver.
- **"The loop is hung."** It was not. A process sample showed it alternating
  between `time.sleep` and an SSL handshake — failing fetches, not a deadlock.
- **"The scanner has a sign error."** It did not. AMD read `+1.0% vs its 30-bar
  mean` while being down 15% over 30 days. Both true: the scanner runs on 15m
  bars, so "30 bars" is 7½ hours. **My first check used daily bars** and would
  have had me report a bug that did not exist. The note not stating its span is
  a real (small) presentation problem; the maths is right.
- **The ledger tears, blamed twice on the wrong thing.** First on my own
  `kill -9`, then on two processes ticking at once. I fixed both and the tearing
  **outlived both fixes**, because the mechanism was in `settle()` the whole
  time: cash computed from a stale in-memory record and written as an absolute,
  so the second of two fills silently undid the first. Two debits recorded, one
  applied. If a bug survives your fix, the fix was for a different bug.
- **Testing a JavaScript page with `curl`.** Three times I told the user the
  site was fine because `curl` returned 200 in 0.1s. `curl` runs no JavaScript.
  When I finally opened a browser, the page was accumulating **88 stuck SVG
  walkers, all mid-walk, none finished** — `requestAnimationFrame` is paused in
  a hidden tab while `setInterval` keeps adding more. That was the "website
  isn't loading" all along. **Look at the thing the user is looking at.**

### A commit that lied about itself

`c404407` reported success having captured **2 of its 4 files**. Another agent
ran `git stash` in this working tree between the edit and the `git add`; the add
staged two files that had been silently reverted, git had nothing to record, and
the commit went through looking complete. Caught only because the loop restarted
and wrote no heartbeat — on a guard whose whole purpose is to make that
observable. **Verify a commit contains what you think it does when anything else
shares the working tree.**

### The cost of a shared environment

Another session working in this repo:

- switched the branch under a running loop, so the village ran unfixed code;
- **uninstalled `certifi`**, which broke every Alpaca fetch — the loop could not
  price anything and looked hung for hours;
- removed `pytest`, then `httpx2`, breaking the suite twice.

All three restored. Now prevented structurally: separate worktrees and separate
venvs. `hive_mind` needs **zero third-party packages**, so its venv is empty and
its installs cannot touch the village's 30.
